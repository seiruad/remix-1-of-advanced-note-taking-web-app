# Контекст папки — в сегмент Folders

Убираем отдельную полосу-«навес» с названием папки под переключателем. Вместо неё сам сегмент `Folders` внутри папки превращается в контекст папки: назад, название, счётчик и меню.

## Как это выглядит

Верх сайдбара остаётся одной строкой (h-11, как сейчас):

```text
вне папки:   [ ▤ All Notes ][ ⌸ Folders ]
внутри:      [ ▤ All Notes ][ ‹ ● Library  2  ⋯ ]
```

- Левая половина `All Notes` не меняется — переключение работает и внутри папки.
- Правая половина в состоянии «внутри папки» становится контекст-чипом: `‹` (назад к списку папок), цветная точка, название (truncate), счётчик заметок, `⋯`.
- Цвет точки и акцент — по типу папки: обычная (emerald), новая (amber + бейдж New при наличии места), «No Folder» (slate, курсив, без меню).
- `⋯` открывает `UnifiedMenu` с Rename / Delete; Rename переводит название в инлайн-инпут прямо в чипе.
- Ниже сразу идёт список заметок — вторая строка исчезает, экран становится на ~44px выше.
- Кнопка `New Note` внизу остаётся без изменений.

Стиль — как в остальном `UnifiedSidebar`: `bg-slate-900/60` контейнер, активный сегмент `bg-slate-700` + emerald-текст, тач-таргеты не меньше 32–36px, mobile-first.

## Технически

Правки только в `src/components/UnifiedSidebar.tsx`, компонент `SidebarNavBar`:
- Удалить блок «folder context strip» (`insideFolder && crumbInfo` строка h-11).
- Внутри сегмент-контейнера при `mode === 'folders' && selectedFolderId` рендерить контекст-чип вместо кнопки `Folders`: внутренняя кнопка `‹` вызывает `setSelectedFolderId(null)`, остальная площадь чипа тоже кликается как «назад».
- Перенести существующие `isRenaming` / `renameValue` и `UnifiedMenu` (Rename, Delete) в чип; логика `onRenameFolder` / `onOpenDeleteFolder` не меняется.
- `crumbInfo` переиспользуется как есть; для «No Folder» меню не показываем.

Бизнес-логика, создание заметок, поиск и списки не трогаются.
